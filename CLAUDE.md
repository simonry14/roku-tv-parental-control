# CLAUDE.md: Roku TV Parental Control handoff

(Called “Roku Guardian” until v1.0; see decision 43 for the names that were kept.)

LAN parental-control service for a Roku TV. A single Node/TypeScript process on an always-on Windows PC polls the TV over Roku ECP (unauthenticated HTTP on :8060), records sessions in SQLite, enforces app policy, schedules and budgets, and serves a PIN-protected React dashboard with ntfy notifications. A sideloaded BrightScript channel (`roku-channel/`) shows the reasons and countdowns on the TV. It runs as a Windows service (node-windows) with rotating logs and nightly backups.

The owner is a full-stack developer (Azure, SQL, Node/React) and expects production-quality, typed code with tests. Time zone: **America/New_York**. The original build prompt is in the owner's chat and not in the repo; the key requirements are summarised under _Roadmap_ below.

```bash

npm run mock-roku          # mock TV: ECP :8060, control panel/API :8061, SSDP udp 1900

npm run status:mock        # CLI readout against the mock DB
npm run dev                # service → real TV (config.json)
npm run status | discover | sessions | apps | events
npm run pause -- 30 | resume | lock [-- 30] | unlock | bonus -- 15   # parent overrides (DB)
npm run set-pin -- <digits> # dashboard PIN (only way to create it)
npm run setup              # the wizard: TV, PIN, rules, TV channel (Install.cmd runs it with --installer)

npm run channel:build      # roku-channel/ → roku-channel/out/parental-control-channel.zip
npm run channel:install    # sideload it (Digest auth, user rokudev; ROKU_DEV_PASSWORD or --password; --host/--port)
npm run message -- "Hi"    # show a message on the TV directly over ECP (--test for the sample)
npm run backup [-- --list] # back up the DB now / list backups
npm run service:install    # Windows only, elevated: build + install + start the service (also :uninstall :start :stop :restart :status)
npm run build:web          # dashboard → web/dist (served by the service on http.port, default 8090)
npm run dev:web            # Vite dev server :5173, proxies /api → :8090

npm run check              # tsc --noEmit + eslint + vitest
npm run build && npm start # tsc → dist/, runs dist/src/server.js
```

Mock control API (the tests use the in-process `MockRoku` object directly):

- `POST /api/remote {"launch":"12"} | {"key":"PowerOff"}`: the kid pressing the remote. Not recorded in history.
- `POST /api/state {"access":"limited"|"disabled"|"enabled","offline":true,"power":"DisplayOff","screensaver":true,...}`
- `GET /api/history`: ECP **commands** received (POSTs). The enforcer tests assert keypresses with it.
- `config.mock.json` runs in `enforce` mode with demo rules: 837 and 2285 blocked, 44444 limited to 2 min, quiet hours 22:00–06:00. (Quiet hours make evening UI testing awkward: test with a copy that has the quiet hours removed.)
- The "Time's up" channel: `/launch/dev?…` and `/input?…` store their params in `state.devMessage` (the panel decodes the title); `Select` on a dismissable message closes it (→ Home); `history[].query` keeps the params. `devChannelInstalled` defaults to **true**, so the plain Home/PowerOff tests (`enforcer.test.ts`, `api.test.ts`) set it to false; `tv-messages.test.ts` covers the channel.
- Developer installer: `startMockRoku({ devInstaller: { port, password } })`; the CLI mock listens on :8062 with password `mock`. Digest MD5/qop=auth like the real TV; it reads `build_version` from the uploaded manifest into `state.devChannelVersion` and records `sideloads`.

## Architecture

```
server.ts ──► app.ts (composition root: createGuardian(config, logger, overrides))
                 │
                 ├─ db/database.ts   openDatabase: WAL, busy_timeout, migrations
                 ├─ db/repo.ts       Devices / Apps / Sessions / Events / KeyValue(settings|runtime_state)
                 ├─ ecp/locator.ts   DeviceLocator: manual host → last-known → SSDP → subnet scan; pins by serial
                 ├─ monitor/poller.ts   loop: device-info (+active-app) → Observation → SessionTracker → health → bus
                 │     ├─ ecp/client.ts        EcpClient (node:http, typed EcpError kinds)
                 │     ├─ ecp/reachability.ts  ping + ARP MAC (tamper vs. DHCP move)
                 │     └─ monitor/sessions.ts  planSessionOps (pure) + SessionTracker (transactional)
                 ├─ usage/usage.ts   summarizeUsage (pure, day-clipped) + UsageService
                 ├─ enforce/enforcer.ts  on bus "observation": rules/engine.evaluate → cooldown → escalation → act
                 │     ├─ rules/engine.ts + schedule.ts  pure: (observation, rules, usage, override, bonus, now, zone) → Decision
                 │     ├─ enforce/tv-messages.ts  pure: Decision → TvMessage (the words on the TV) → channel params
                 │     └─ enforce/messenger.ts    TvMessenger: /launch/dev or /input; installed = TV's channel list
                 ├─ ops/backup.ts    BackupService: nightly db.backup() → data/backups, keep N
                 ├─ lib/log-file.ts  RotatingLogFile (pino destination; daily + size, keepDays)

                 ├─ settings/runtime.ts  RuntimeConfig: dashboard overlay (settings table) > config.json; emits "change"
                 ├─ api/server.ts    Fastify (started in guardian.start()): LAN guard, JSON-only mutations, auth, routes, SSE, static SPA
                 │     ├─ api/auth.ts     PIN (argon2id) + opaque session tokens (sha256 in auth_sessions) + lockout
                 │     ├─ api/status.ts   DTO builders (status, apps, usage days); api/contract.ts = shared DTO types
                 │     └─ api/icons.ts    icon cache (app_icons table, 7-day TTL, placeholder tile fallback)
                 └─ lib/bus.ts       GuardianBus (typed EventEmitter): observation | health | session | device | enforcement

web/ (Vite + React 19 + Tailwind v4, built to web/dist): App.tsx (auth gate, hash tabs) → views/{Now,Rules,History,Settings,Login}
     hooks.ts useLiveStatus = EventSource(/api/stream) with polling fallback; api.ts typed fetch client (imports src/api/contract.ts)

roku-channel/ (BrightScript/SceneGraph, 1920×1080): source/main.brs parses launch/input params → components/MessageScene
     src/channel/{zip,package,sideload}.ts build the zip and install it; src/cli/ops.ts = channel:build/install, message, backup
service/launcher.mjs → dist/src/server.js   (src/cli/service.ts installs it with node-windows; wrapper files in service/daemon/)
```

The poller publishes to the **bus**. The enforcer, the notifier and the SSE stream all subscribe to it; nothing reaches into the poller except through its public methods (`sendKey`, `launch`, `input`, `foregroundAppId`, `refreshApps`, `pollNow`, `rediscover`, `fetchIcon`, `reportControlRestricted`). `observation` fires after every tick with the observation and a `LiveStatus` snapshot.

## Key decisions and invariants

1. **Session accounting (do not break this).** Counted time = the sum over consecutive _successful_ polls that saw the same activity and are ≤ `maxGapSec` apart. So `ended_at` is always equal to `last_seen_at`; the DB enforces this with a CHECK. Every close happens at the last confirmed poll, and a new session starts at the poll that saw it. `unknown` observations never extend a session. A single failed poll is tolerated, but past `maxGap` the session closes with reason `unreachable`/`restricted`. There is at most one open session, enforced by the partial unique index `sessions_single_open`. The property test in `tests/unit/sessions.test.ts` checks this against a reference model. The open session's usage runs up to `last_seen_at`.
2. **Restarts:** `stop()` leaves the open session open. `recover()` on start closes it only if it's stale (older than maxGap), so a quick restart continues the session seamlessly.
3. **Days** come from `localDayRange(ms, config.timezone)`, never `+86400000`. Usage clips sessions to [dayStart, dayEnd).
4. **Limited-mode canary.** Roku docs (OS 14.1+) say keypress, keydown, keyup and `query/icon` need "Control by mobile apps = Enabled", while device-info and active-app keep working. So monitoring can look healthy while enforcement silently fails. The poller GETs `/query/icon/{installed appl id}` every `restrictionProbeIntervalSec` (every 15 s while Limited). `Poller.reportControlRestricted()` exists so the enforcer can flag a 403 on a keypress immediately. **Phase 2 must call it.**
5. **Refused ≠ tamper.** ECONNREFUSED on :8060 proves _a_ host is up at that address (it sent a TCP RST). It's either our TV with ECP disabled, or another device that DHCP gave the address to. The triage uses the ARP MAC (`arp -a` / `ip neigh`; ping first to refresh the entry):
   - MAC mismatch → rediscover.
   - MAC unknown → rediscover once _before_ raising `restricted/disabled`.
   - MAC match → it's our TV, so flag it.

   Results are cached for 30 s. Windows ping exit codes lie, so we check for `TTL=` instead; ping isn't used for the decision anyway.

6. **Refused but announced = still our TV.** Observed on the owner's real TV (2026-09-30): with "Control by mobile apps" set to **Disabled**, SSDP still answers normally but _every_ ECP query returns HTTP 403, and the port stays open. So Disabled = `restricted/blocked`, flagged on the first poll. The mock's default `disabledBehavior` is now `403` to match; `refuse` remains for other firmware. Limited mode behavior on this TV is not yet observed. The locator therefore pins a device when its probe is refused (403, or ECONNREFUSED right after SSDP announced that serial at that address), identifying it by the USN serial. The poller then reports `restricted` with the fix instead of "no Roku found". Tests: `pins a TV found by SSDP even when it refuses ECP`.
7. **Pinning** is by serial (DB `devices.pinned`, with a unique partial index). A different serial answering at the pinned address is never tracked.
8. **Backoff:** only while `offline`/`searching`, doubling from the poll interval up to `offlineBackoffMaxSec` (30 s). While `tv_off`, polling stays at 5 s so a quiet-hours power-on is caught quickly.
9. **node:http, not fetch.** This gives precise error codes and a hard per-request deadline, with no keep-alive against the Roku's simple server.
10. **Migrations are embedded in TS**, so `dist/` has no assets to copy.
11. **TypeScript 6.0.x pinned** (`~6.0.3`). TS 7 (the Go port) is the npm `latest` but typescript-eslint supports <6.1. Revisit when typescript-eslint supports TS 7.
12. **`.npmrc` sets `ignore-scripts=true`.** Keep it. better-sqlite3 13 bundles its prebuilds and sets `"gypfile": false`, but npm (every version, including 11) drops that flag when building the tree from `package-lock.json`, sees `binding.gyp`, and runs `node-gyp rebuild`. On Windows without the VC++ toolset that fails; this was hit on the owner's PC. No current dependency needs an install script. If you add one that does (check `hasInstallScript` in the lockfile), run its script explicitly or rethink this.
13. **Deps:** better-sqlite3 13 (requires Node ≥22), fastify 5 (+ cookie, rate-limit, static), @node-rs/argon2, zod 4, pino 10 (+ pino-pretty on a TTY), luxon, fast-xml-parser, node-windows (beta; CJS, loaded with `createRequire`, no install script). ESM with `.js` import suffixes (NodeNext).
14. **Settings precedence:** defaults < config.json < DB `settings` table (`overlay.<section>`), for rules, enforcement, notifications, device, monitor and tvMessages. See decision 24.

### Phase 2 decisions

15. **Schedules compare local wall-clock minutes** in `config.timezone` (Luxon), never elapsed ms since midnight. "Quiet hours until 07:00" ends at 07:00 on the clock on 23- and 25-hour days. On the fall-back day, the repeated hour is inside a window both times. A window starting in the spring-forward gap opens at 03:00. All of this is covered by tests.
16. **Only schedules and locks power off.** App rules only press Home, and Home/screensaver are never app-blocked. Quiet hours and outside-window apply to _any_ screen, including Home.
17. **Escalation counts any app-rule Home press** in the window, not just the same app. That way a kid can't dodge it by rotating between blocked apps. Deviation from the prompt's "same violation": say so if the owner objects.
18. **Default enforcement mode is `dry-run`.** Actions are logged as `DRY RUN: would send …`. `off` still evaluates (for `status`) but neither acts nor logs. The owner flips to `enforce` after watching the dry-run log.
19. **The rules and enforcement sections of config.json hot-reload** (a directory `fs.watch` with a 500 ms debounce, since editors replace files). An invalid file keeps the previous rules. Other sections need a restart.
20. **Overrides and bonus time live in SQLite** (migration 2: a singleton `overrides` row, `bonus_time` per local day). The CLI writes them and the service reads them every tick, so there's no IPC. Phase 3's dashboard should use the same repo (`repos.overrides`). `lock` from the CLI also sends PowerOff immediately (even in dry-run); keeping it off afterwards needs `enforce`.
21. **Cooldown timestamps update even when a keypress fails**, so a broken or restricted TV isn't hammered.

### Phase 3 decisions

22. **The PIN is created only on the PC** (`npm run set-pin`). The dashboard can _change_ it (it needs the current one) but never create it, so a kid on the Wi-Fi can't claim a fresh install.
23. **No TLS.** It's plain HTTP on the home LAN. Protection is the LAN-only guard + a firewall rule scoped to LocalSubnet + an HttpOnly/SameSite=Strict cookie + JSON-only POST/PUT/PATCH (CSRF). Never port-forward it. If remote access is ever wanted, put it behind Tailscale or a reverse proxy with TLS rather than exposing it.
24. **Dashboard edits override config.json per section** and persist in SQLite. Hot reload of config.json still works, but the overlay wins for any section edited in the dashboard, until it's reset. The UI shows the source.
25. **The poll interval is live**: `maxGapMs = max(config.maxGapSec, 3 × poll)` is re-applied to the tracker on change.
26. **Icons** require "Control by mobile apps = Enabled" (same as keypress). They're cached in SQLite for 7 days; failures return a generated initials tile with `max-age=60`, so they retry soon.
27. **UI copy rules**: plain sentence case, no all-caps labels, no " · " meta strings; server messages' " — " is rendered as ": ". The TV screen is the one loud element; status colours are only used for health.
28. **web/dist is git-ignored** but was copied to the owner's folder so the dashboard works without a build. Rebuild with `npm run build:web` after changing web/.

### Phase 4 decisions

29. **Channel protocol v1** (`roku-channel/source/main.brs` is the reference): `v, kind, t, b, cd, ct, ce, ok`. Text is base64url UTF-8 so nothing depends on how the TV URL-decodes; `ct` uses `^0`/`^1` for seconds and "second(s)". The channel is presentation only; every word comes from `tv-messages.ts`.
30. **Messages replace Home** for app rules (opening the channel ends the app just like Home), and they **precede PowerOff** with a countdown for schedules/locks. Countdown lengths: `countdownSec` (30) the first time; `shortCountdownSec` (10) for locks, escalation, and a TV switched back on within 10 min of a PowerOff. While a countdown runs nothing else is enforced. It's cancelled (message closed with Home) if the TV goes off, rules are paused, the lock is lifted, the schedule no longer applies, or the mode leaves `enforce` (except a dashboard lock, which is `force`). Pressing Home on the TV does **not** cancel it. Unreachable during a countdown: keep waiting up to 1 min past the end.
31. **Fallbacks:** channel not in the TV's list, or `tvMessages.enabled=false` → plain keys. A launch 404 → treated as missing for 10 min + app-list refresh + Home/PowerOff now. A 403 → `reportControlRestricted()` and a failed event (keys would fail too).
32. **Warnings are off by default** (`warnBeforeMin: 0`): they interrupt the show and some apps reopen at their home screen. When on: the nearest of global budget / app budget / end of allowed schedule, once per scope per local day, re-armed if more than threshold + 1 min becomes available (bonus). After `warningSec` the enforcer relaunches the app; OK (→ Home) within the grace period (20 s) also returns.
33. **Channel layout is manual** (`Layout()` measures `BoundingRect()`), not a LayoutGroup: in the brs-engine simulator, LayoutGroup didn't account for wrapped Label heights (title and body overlapped). Manual layout behaves the same on real Roku OS. Labels need explicit `width` for wrapping.
34. **The enforcer is single-threaded by a promise queue.** Polls that arrive while it's busy are skipped (the next poll re-evaluates); API actions (lock, message) wait their turn. `idle()` returns the queue for tests.
35. **Logging runs in-process** (`pino.multistream`), not in a transport worker: a few lines a minute, and synchronous writes survive crashes. Rotation is close → rename → reopen (never rename an open file on Windows). In service mode the console gets warn+ only (winsw keeps its own rotated copy in `logs/service/`).
36. **Backups** use better-sqlite3's online `db.backup()` (consistent under WAL while the service writes). Checked every 10 min, so a sleeping laptop backs up when it wakes; one file per local day; `keep` newest.
37. **Windows service via node-windows** (winsw). The script is `service/launcher.mjs` because node-windows puts its wrapper files beside the script and `dist/` is deleted on each build. `stopparentfirst: true` makes the wrapper send IPC `'shutdown'` (server.ts handles it → graceful stop); crashes restart after 2 s growing ×1.5, ≤5 per minute. Runs as LocalSystem from the project folder. NSSM documented as the alternative (README §13).
38. **Single instance:** at start, if `runtime_state.service.pid` is another process that is alive (`process.kill(pid, 0)`; EPERM counts as alive, since the service runs as SYSTEM) and the `live` heartbeat is under 2 min old and not marked stopped, a terminal run exits with code 3 and a message; the service waits and retries every 15 s.
39. **CLI `lock` stays an immediate PowerOff** (a CLI process can't own a countdown); the dashboard lock shows the 10 s countdown. `npm run message` talks to the TV directly and has no "go back to the show".
40. **Every TV message is a template the parent can rewrite** (asked for 2026-10-01). `tvMessages.texts` keeps only fields that differ from the defaults (`compactTexts`), so "Use the original words" = leave it out. Fill-ins: a value of `''` disappears and the sentence is tidied ("locked the TV {until}." → "locked the TV."); `null` (unknown, e.g. no upcoming TV time, no limit set) drops the whole line. Validation (zod `superRefine` with `textProblems`) rejects unknown keys/fields, unknown fill-ins and over-long text with sentences the dashboard shows as-is. `^` is stripped (the channel's `^0`/`^1`). Bodies may contain `\n` (Labels with `wrap` honor it in brs-engine; unverified on Roku OS). The global-budget default carries the owner's line "To get more time on the TV, read a book, do a chore or practice Python programming." The short-lived `timesUpTip` field (v0.4.0, a few hours) is migrated by a `z.preprocess` in `TvMessagesConfigSchema`. Not editable: "Press OK to close", the brand line and the channel's idle screen (they live in the channel). `npm run message` uses the dashboard's words too (RuntimeConfig over the DB).
41. **Service start-up hardening (v0.5.1).** On 2026-10-04 a Windows Update restart left the service "running" (winsw + node-windows wrapper alive, `Started <pid>` in `logs/service/rokuguardian.wrapper.log`) while the app never wrote a log line, its stdout/stderr were empty, the DB was untouched, and the dashboard refused connections. The cause wasn't visible from the project folder (the wrapper only logs to the Windows Event Log). So: `service/launcher.mjs` writes `logs/service/launcher.log` (start, running, waiting, could-not-start + reason, exit code) before importing the app, and runs a 3-minute watchdog that exits (→ wrapper restarts) if `server.ts` hasn't emitted `roku-guardian:started` (process events `loaded`/`started`/`waiting`/`failed`; a build without `loaded` disarms it). `service:install/start/restart` also set `start= delayed-auto`, `sc failure … restart/10000/restart/30000/restart/60000` and `failureflag 1`. `service:status` probes `/api/health` and the `live` heartbeat, so "service running, app dead" is visible. **Next time it happens, read launcher.log and the Application event log (source "Roku Guardian wrapper").** A watchdog can't catch a hang inside a synchronous native call (blocked event loop).
42. Fastify's deprecated `disableRequestLogging` was replaced by `logController: new LogController({ disableRequestLogging: true })`.

## Conventions

- All timestamps are **UTC epoch ms** (INTEGER). Local time appears only at the edges (day ranges, display).
- Pure logic (`xml.ts`, `planSessionOps`, `summarizeUsage`, and the rules engine to come) takes `now` as an argument and never calls `Date.now()`. Components take a `Clock`.
- Components are built only in `app.ts` (the composition root). Tests pass `GuardianOverrides` (db, clock, reachability, ssdp, scan, createClient).
- Logging: pino child loggers with `mod`. Don't use `name` as a log field, because it collides with the logger name.
- Formatting: prettier (120 columns, single quotes). Run `npm run check` before handing off.
